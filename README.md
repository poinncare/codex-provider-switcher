# Codex Launcher

Небольшой macOS-launcher для ChatGPT/Codex, который открывается как обычный Codex и позволяет выбрать подписку Codex или подключённого внешнего провайдера из одного графического меню.

Проект не является продуктом OpenAI и не содержит авторизационных данных.

## Возможности

- обнаруживает аккаунты Codex через Orca и локальные данные Codex;
- переключает аккаунт без повторной авторизации;
- показывает в меню три пункта: Codex, OpenRouter и OpenCode;
- показывает OpenRouter и использует только модели с нулевой ценой при получении списка;
- синхронизирует модели Codex с моделями OpenCode: при выборе OpenCode список моделей Codex полностью заменяется бесплатными моделями самого OpenCode, поэтому в Codex видны те же модели, что и в OpenCode, а не встроенные модели Codex;
- направляет каждый запрос Codex в тот upstream и с теми ключами, которые OpenCode указал для выбранной модели, и никогда не подставляет свои ключи;
- не требует выбора модели: провайдер подключается напрямую, а модель выбирается уже в интерфейсе Codex;
- перезаписывает свои секции `[model_providers.*]` с `wire_api = "responses"`, поэтому старые названия и устаревшие блоки не накапливаются;
- перезапускает только настольный ChatGPT/Codex-сервер, не трогая терминальные сессии;
- хранит ключ OpenRouter в macOS Keychain, а не в файле проекта.

## Требования

- macOS;
- установленный ChatGPT/Codex;
- Orca — для обнаружения уже зарегистрированных аккаунтов Codex;
- OpenCode — для пункта OpenCode: модели и учётные данные берутся из самого OpenCode (его локального API), дополнительных ключей в проекте не хранится;
- Python 3, AppleScript и стандартные macOS-команды (osacompile, security, ditto).

## Установка

~~~sh
git clone https://github.com/<owner>/codex-provider-switcher.git
cd codex-provider-switcher
./scripts/install.sh
~~~

После установки приложение появится в `~/Applications/Codex.app`. Именно его нужно закрепить в Dock и запускать вместо отдельного свитчера.

Официальное приложение ChatGPT/Codex не изменяется и остаётся доступным для прямого запуска из `/Applications/ChatGPT.app`.

Для OpenRouter ключ можно сохранить в Keychain:

~~~sh
./scripts/configure-openrouter.sh
~~~

Обычная работа выполняется через `Codex.app`: открыть Codex → выбрать Codex, OpenRouter или OpenCode. При выборе Codex появится список обнаруженных email аккаунтов и пункт добавления нового аккаунта.

При добавлении нового аккаунта launcher открывает Terminal и запускает обычный `codex login` в отдельном временном `CODEX_HOME`. После входа через браузер авторизация копируется в отдельное хранилище аккаунта и добавляется в локальные данные Orca. Текущая активная сессия и её привязка не изменяются. Для этого сценария не используется `codex login --device-auth`, поэтому разрешение Device Code Authorization в ChatGPT не требуется. Хранилище авторизации для временного входа принудительно выбирается как локальный файл, чтобы аккаунт можно было безопасно зарегистрировать и потом переключать.

При выборе аккаунта свитчер меняет только активную OAuth-сессию в штатном `~/.codex/auth.json` и запускает ChatGPT без `CODEX_HOME` и Orca-окружения. Поэтому проекты, история и настройки остаются теми же, что при обычном запуске ChatGPT/Codex. Данные Orca и привязки его панелей при этом не изменяются, а Orca не запускается повторно.

## Как выполняется обнаружение

1. Аккаунты Codex берутся из команды Orca account list --json, затем из Orca orca-data.json. Если CLI Orca недоступен, используется локальная Codex-сессия как резервный источник.
2. Меню состоит из трёх пунктов: Codex, OpenRouter и OpenCode. Провайдеры не угадываются по конфигурации OpenCode — за пункт OpenCode отвечает сам OpenCode.
3. Для пункта OpenCode launcher читает список моделей у запущенного сервиса OpenCode (`GET /api/model`), при необходимости разбудив его командой `opencode models`. В список попадают только **бесплатные** модели — те, у которых OpenCode указывает нулевую цену на всех тарифах и есть окно контекста. Платные модели скрыты намеренно: у Codex нет собственных ключей, и такой запрос всё равно упёрся бы в оплату. Модели, ведущие в другой локальный шлюз, тоже не берутся: локальный шлюз — чужая зона ответственности, проект им не управляет.
4. Затем launcher поднимает свой локальный роутер (`src/opencode_router.py`, по умолчанию `127.0.0.1:20130`) и перезаписывает секции `[model_providers.openrouter]` и `[model_providers.opencode]` в `~/.codex/config.toml`, всегда проставляя `wire_api = "responses"`. Секции, которыми владеет launcher, предварительно удаляются, поэтому переименования, старые имена вида `opencode-*` и устаревшие блоки не остаются в конфиге.
5. Список моделей синхронизируется с OpenCode. Codex полностью заменяет свой список моделей на каталог из ключа `model_catalog_json`, поэтому launcher при каждом переключении пишет в `~/.codex/codex-provider-switcher-models.json` весь список **бесплатных** моделей OpenCode с их именами и длиной контекста и прописывает путь к нему в `~/.codex/config.toml`. Стартовая модель берётся из того же списка (модели, которые вы недавно использовали в OpenCode, идут первыми), поэтому Codex открывается на модели своего провайдера. При выборе Codex или OpenRouter ключ удаляется и возвращается штатный список моделей. Свой путь к каталогу можно задать переменной `CODEX_MODEL_CATALOG_JSON`.
6. Роутер не хранит ключей: по каждому запросу он берёт из списка OpenCode нужный upstream (`baseURL`), ключ (`apiKey` из настроек модели или из `auth.json` OpenCode) и дополнительные поля запроса, подменяет имя модели на upstream-имя и передаёт ответ как есть. Если upstream не отвечает, Codex получает его ошибку без искажений.
7. OpenRouter всегда доступен в меню, а его ключ ищется в Keychain по сервису codex-provider-switcher.openrouter. Для совместимости также проверяется старое имя сервиса com.openai.codex.openrouter.

Пути строятся от домашней директории текущего пользователя. В проекте нет привязки к конкретному имени пользователя, email, account ID или абсолютной папке разработчика.

## Разработка

Проверить синтаксис:

~~~sh
python3 -m py_compile src/codex_provider_switcher.py src/opencode_router.py
python3 src/codex_provider_switcher.py list-providers
python3 src/codex_provider_switcher.py prepare-accounts
python3 src/opencode_router.py catalog   # модели, которые Codex получит от OpenCode
python3 -m unittest discover -s tests
~~~

Собрать приложение:

~~~sh
./scripts/build-app.sh
~~~

Готовое приложение будет в dist/Codex.app. dist/ не включается в Git, потому что AppleScript внутри .app содержит локальный путь к backend текущей установки; его генерирует сборочный скрипт.

## Безопасность

Не добавляйте в Git:

- auth.json;
- ключи OpenRouter;
- конфигурации с токенами;
- содержимое ~/Library/Application Support/orca;
- личные email и account ID.

Перед публикацией проверьте:

~~~sh
git grep -n -i -E 'sk-or-|access_token|refresh_token|auth\\.json|/Users/|@gmail\\.com'
~~~
